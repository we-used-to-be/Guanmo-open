# 优化 AI 回答与检索策略

## Goal

降低普通 AI 问答的结构与来源噪声，同时让本地研究、RAG 索引和改写风格记忆按用户真实意图触发。

## Background

- 普通解释受全局可信回答提示影响，容易机械拆成“结论、推断、信息不足”。
- `AiPanel.tsx` 对几乎所有无来源的助手消息展示“本次回答未使用本地文档来源”，全局提示词还要求模型重复声明。
- `isLocalResearchIntent()` 只有在“研究/归纳”等动作词与“知识库/本地资料”等来源词同时出现时才触发，主题研究无法直接进入全库检索。
- `scheduleMarkdownDocumentIndex()` 对手动保存、自动保存和打开文件共用 1200ms 延迟；自动保存后仍会较快启动索引。
- `classifyMemoryRetrievalIntent()` 在识别风格信号前排除改写、润色、重写任务，导致个性化改写无法读取风格记忆。

## Requirements

- R1 普通解释和普通问答应按问题复杂度组织答案，优先直接、简短表达，不强制可信回答分区。
- R2 总结、研究、Web 对照等任务保留结构化输出；来源支持范围、推断和信息缺口仍须诚实表达。
- R3 普通无来源回答不展示来源区域，也不要求模型声明“未使用本地文档来源”。实际存在本地或 Web 来源时继续展示 `Sources`；研究任务检索失败时在回答中说明资料不足。
- R4 “研究/调研某主题”等明确研究动作可直接触发全库 `search_knowledge`，无需 tag；普通知识问答继续留在非 Agent 链路。
- R5 “归纳/总结指定文件”继续要求 file tag 以精确读取；任何文档改写继续要求本轮 selection/file tag 和确认卡片，不放宽写入授权。
- R6 手动保存保持较快索引，自动保存采用更长的空闲防抖；同一文件的重复索引任务继续合并，增量索引和串行保护不变。
- R7 只有出现“按我的风格、照旧、沿用以前语气”等个性化信号的改写请求才检索长期记忆；普通改写不增加记忆检索。
- R8 风格检索只注入与偏好、指令相关的有效记忆，不改变长期记忆写入规则。
- R9 精准修改任务文件，不覆盖 `src/services/rag/indexer.ts`、`src/services/rag/pipeline.ts` 等现有未提交改动；不执行推送。

## Acceptance Criteria

- [x] AC1 普通解释提示明确要求“能一句说清就不分段”，且不再包含无来源强制声明。
- [x] AC2 无 `sources` 的普通助手消息不渲染来源占位；有来源消息仍可展开查看本地或 Web 来源。
- [x] AC3 “研究 Node.js 单线程”等明确研究请求进入本地研究链路且无需 tag；“Node.js 单线程是什么”不进入 Agent。
- [x] AC4 “归纳这个文件”在无 tag 时不伪装成精确文件总结；改写无 tag 时仍拒绝，现有确认卡片边界不回归。
- [x] AC5 自动保存后的索引延迟高于手动保存；相同文件连续调度只执行最后一次内容。
- [x] AC6 “帮我按我的风格改写这段”触发轻量风格记忆检索；“帮我改写这段”不触发记忆检索。
- [x] AC7 `npm run test:agent-parser`、`npm run test:memory`、`npm run test:rag-index`、`npm run build`、`git diff --check` 全部通过。
- [x] AC8 最终 diff 仅包含本任务必要修改，现有脏工作区文件边界已核对。

## Out of Scope

- 不新增 AI 模式切换 UI、来源可信度评分或管理页面。
- 不改变 Web 搜索授权、文件写入确认、记忆写入和跨工作区记忆隔离规则。
- 不把“归纳”单词无条件视为全库研究；必须能识别其目标是主题研究，而非指定文件或当前文本整理。
