# 优化长期记忆触发与归纳

## Goal

提高日常对话中长期记忆的召回率和自动候选质量：能够识别用户对既有惯例的隐式续接，同时避免翻译、总结、代码解释等转换型请求误触发；自动提取结果应是短小、稳定、可合并的结构化事实。

## Background

- 当前 `classifyMemoryRetrievalIntent` 会因“之前、上次、曾经”等宽泛词单独出现而触发弱检索，且尚未覆盖“照旧、老规矩、像平时一样”等日常表达。
- 当前归纳链路已有基础过滤、文本相似候选刷新和 active 冲突替换，但候选规范化、同一事实合并与冲突决策仍分散在 `memoryService.ts` 中，专项测试难以直接覆盖。
- 现有检索入口、数据库 Schema、设置页确认/归档流程必须保持兼容。

## Requirements

- R1：明确查询用户记忆、偏好或长期约定仍分类为 `strong`。
- R2：惯例续接表达分类为 `weak`，至少覆盖“照旧、老规矩、还是按原来、继续沿用、像平时一样、按常用方式”。
- R3：单独出现历史时间词不得触发弱检索；翻译、总结、改写和代码解释不得因待处理文本中的记忆关键词误触发。
- R4：提取 prompt 要求每项只有一个跨会话稳定事实，正文为不超过 80 个 Unicode 字符的中性单句；多事实拆分，拿不准时输出空数组。
- R5：候选进入持久化前统一规范化并拒绝临时信息、转换型内容、源码/正文摘录、空泛表述、多句说明和超长内容。
- R6：同一事实优先按作用域、主体和事实键识别；缺少结构化字段时，仅在同类别、同作用域内使用文本相似度兜底。
- R7：相同事实和值不新增；命中未锁定自动候选时保留 ID、创建时间和状态，采用更短的有效表述，等长时保留旧表述，并补齐结构字段、提高置信度、刷新原始证据。
- R8：同一未确认候选出现新值时复用旧 ID；active 同键同值跳过，同键异值创建唯一 replacement candidate 并设置 `supersedesId`。
- R9：不得跨类别或项目作用域合并，不得修改锁定或人工维护的记忆；正文变化时清空 embedding 缓存，无实质变化时不持久化且不计入新增数。
- R10：按阶段串行实施，阶段 1 专项测试通过后才能进入阶段 2。

## Acceptance Criteria

- [x] 明确记忆查询为 `strong`；惯例续接为 `weak`。
- [x] “总结上次会议”“解释之前的代码”“翻译包含‘你还记得我’的文本”和普通代码分析均为 `none`。
- [x] 稳定偏好、称呼、长期项目约定可通过候选过滤。
- [x] 临时状态、转换型内容、虚构内容、超过 80 字和多句说明被拒绝。
- [x] 同批次及已有的近义候选只保留一个 ID，并采用更短的规范表述。
- [x] active 同键同值不入库，同键异值生成唯一替换候选，不同作用域互不影响。
- [x] `npm run test:memory` 在两个阶段检查点均通过，最终 `npm run build` 通过。

## Out of Scope

- 不修改数据库 Schema、公共 API、设置页 UI 或 `AGENTS.md`。
- 不处理现有无关的 `src-tauri/Cargo.lock`、Trellis 初始化文件和 Playwright 产物。
- 不提交、不推送。
