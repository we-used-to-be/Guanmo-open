# 记忆独立缓存召回验证（2026-10-29）

最后收尾核验：2026-10-30。隔离实例已退出，临时复制的 DeepSeek 对话及硅基流动 Embedding 绑定均已移除；正式观墨实例保留。

## 自检结论

- `useAiChat.ts` 的按需预检索和 Agent `search_memory` 均调用 `searchMemories`；路由及轻模型触发本次未修改。
- 原轻检索仅加载词法前 12 条的向量；无词法匹配时直接返回空。强检索仅在完全无词法匹配时兜底前 40 条；只要存在正词法匹配，其他记忆仍无法参与语义排序。
- 即使存在词法重合，相关记忆也可能被前 12/40 条挤出。旧实现没有独立语义候选扩展。
- SQLite 缓存已有模型名、内容哈希与向量，技术上可按全部有效 ID 读取；但每轮解析全部 JSON 向量会增加 IPC、内存和同步计算成本，因此采用有界窗口。

## 修改与边界

- 仅修改记忆服务、对应查询契约检查、RAG/记忆契约，新增固定样例测试；无依赖、schema 或配置变更。
- SQLite 先过滤 active、scope、category，保留原替代关系、敏感信息及来源处理；独立候选也从同一有效集合选择。
- 合并词法前 12/40 条和近期兼容缓存前 256/1024 条，按 ID 去重，每批最多读取 64 个向量，最终优化为最多 4 批并行且每组完成后检查取消。非词法候选余弦门槛默认 0.7；真实验收发现 BGE 中文模型有效改写仅约 0.45，因此仅对 `BAAI/bge-large-zh-v1.5` 校准为 0.4，其他模型保持原门槛。最终沿用融合阈值、TopK 和上下文预算。
- 缓存窗口顺序来自 SQLite `updated_at DESC, id ASC`，不按词法分数选取；小于窗口的有效兼容缓存可全部参与。
- 查询向量每次检索最多一次，保留 1.2 秒超时及取消；读取缓存失败或提供方失败时保留完整词法排序，修复旧路径回退仍被候选截断的问题。
- 记忆向量按原闲时策略补齐词法候选；强检索零词法时保留前 40 条有效记忆的补齐入口，单次最多生成 8 条，不在请求路径等待。普通无记忆意图的问答不会因此触发检索。
