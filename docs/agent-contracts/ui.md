# UI 组件契约

涉及按钮、菜单新增或修改，以及视觉层级调整时，修改前必须读取本文件。

软件自有弹窗的结构、主题令牌和交互约束见 [`modal.md`](./modal.md)，以“设置 → 快捷操作 → 新增操作”弹窗为模板。

- 按钮默认使用 `type="default"`。
- `type="primary"` 仅用于提交表单、确认关键操作等明确的主要操作。
- `type="text"` 用于文字链接样式，`type="danger"` 用于删除等危险操作。
- 紧凑场景使用 `size="small"`；不指定 `size` 时使用默认中等尺寸。

## 全局菜单

- 适用范围：软件自行渲染的右键菜单、按钮触发的操作菜单、筛选和选择下拉菜单；系统原生菜单和原生文件对话框不属于此组件范围。
- 新增或改造菜单必须复用项目共享菜单组件，以 `src/components/common/ContextMenu.tsx` 为现有入口；能力不足时扩展共享组件，不另写一套弹层、菜单项或通用事件处理。第三方选择组件的下拉菜单也须遵守此约束。
- 使用 `ContextMenu` 的 `position` 或 `anchor` 指定位置，使用 `placement` 指定优先方向；通过 `role="menu"`、`role="listbox"` 或 `role="dialog"` 区分动作菜单、选择列表和自定义表单。内容使用 `ContextMenuItem`、`ContextMenuGroupTitle`、`ContextMenuSeparator` 组合；菜单项通过 `selected`、`danger`、`disabled` 表达状态，业务动作执行及完成后的关闭由调用方决定。
- 共享组件统一管理容器的背景、边框、圆角、阴影、间距、层级和主题令牌，以及选项的悬停、按下、聚焦、禁用、选中和危险操作状态。现有 `.gm-menu-option` 反馈应由共享菜单项使用，业务调用方不得靠复制 CSS 或类名冒充组件统一。
- 通用交互统一由共享组件负责：支持坐标或触发元素定位、视口避让、外部点击和 Esc 关闭、菜单项键盘导航、打开时聚焦及关闭后合理恢复焦点；滚动、窗口尺寸变化和卸载处理采用同一策略，内部可滚动内容不应因自身滚动被关闭。
- 允许通过 `children` 或共享组件支持的组合方式自定义内容，包括图标、说明、快捷键、分组、单选、多选及业务控件。自定义内容不能绕过主题、层级和关闭规则；输入控件保留自身键盘操作，不应被菜单导航拦截。
- 菜单动作、选择列表和含表单的弹层须使用相应的可访问性语义；不能为追求复用而把所有自定义内容标成 `menuitem`。动画遵循项目 Motion 规范和 reduced-motion。
- 验收须核对实际入口使用共享容器和菜单项，并验证浅色、深色主题的鼠标反馈及对应键盘交互；只有 CSS 一致或类型检查通过，不能报告全局统一完成。存量独立菜单应在明确的迁移任务中接入，规则更新不代表迁移已完成。
