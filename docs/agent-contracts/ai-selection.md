# AI 与选区契约

涉及 `src/services/rag/semanticChunker.ts`、`read_selection_context`、AI 路由、检索、长期记忆触发或 Agent 事件时，修改前必须读取本文件。

## 模型请求与前缀稳定性

- 新增或调整模型请求时，保持同一请求配置下的系统提示词和工具定义内容、顺序及序列化稳定；必要的策略、权限或能力变化允许产生不同前缀，不得为了缓存绕过工具资格校验或确认边界。
- 时间、用户状态、检索结果等动态信息以当前轮新增的结构化消息提供，避免改写已有系统提示词或历史消息。上下文超限、安全处理及供应商兼容所需的裁剪或降级可改变前缀，须保留现有安全和语义约束。
- 使用供应商支持的结构化消息及原生工具调用格式，不自行拼接角色分隔符模拟对话；不支持原生工具调用的兼容路径须明确限定，不能扩大授权。稳定前缀只创造缓存复用条件，实际命中、延迟与成本以供应商和实测为准。
- 以上为后续修改的目标约束；存量路径按兼容性和授权边界逐步调整，不视为已全部满足。
- DeepSeek 供应商的 Agent 工具结果沿用文本续答，直到适配层支持思考模式所需的 `reasoning_content` 回传。

## 选区语义上下文

- RAG 索引与 `read_selection_context` 共用 `src/services/rag/semanticChunker.ts` 的 AST 语义原子。
- `read_selection_context` 只接受本轮 selection 授权，只返回包含 `role`、`headingPath`、`content` 的 `chunks` 数组。
- `direction=auto` 按相关性读取；`before/after/both` 是方向硬约束，按文档顺序读取，不得让另一方向参与预算竞争。
- Markdown 标题选区必须锚定该标题正文；`direction=after` 的范围包含其子标题，并在下一个同级或更高级标题前停止。
- Level 1 总预算为 700 tokens；仅在信息不足时调用 Level 2，将累计预算扩展到 1400 tokens，且只返回新增语义原子。
- 同一轮禁止跳级、重复读取同一层或自动升级为全文读取。

## AI 回答与检索触发

- 普通问答和简单解释按问题复杂度直接回答，不强制分段；总结、研究、Web 对照或复杂多步骤问题才使用结构化输出。
- 仅要求“翻译”本轮 selection 时必须走非 Agent 直答流程，只输出译文，不生成修改确认卡片，也不得替换原文。
- 只有用户明确要求“翻译并替换原文”、写回或修改原文时，翻译才按文档修改处理；必须携带本轮 selection/file tag，并继续经过修改确认卡片。
- 助手消息只有实际使用本地或 Web 资料时才展示来源；普通无来源回答不展示来源占位。
- 本轮实际注入模型的长期记忆也进入消息来源列表，按记忆 ID 去重并保留内容快照；预检索与工具检索均须登记，正文引用了其他资料时仍展示记忆。记忆不计入文档覆盖范围或知识片段数量。
- 明确的主题研究、调研或归纳可直接检索全库 `search_knowledge`，无需 tag；指定文件总结仍需 file tag，任何文档改写仍需本轮 selection/file tag 和确认卡片。
- 只有要求沿用用户既有风格、语气、格式或习惯的改写才轻量检索 `preference/instruction` 长期记忆；普通改写不检索记忆。
- 手动保存沿用 1.2 秒 RAG 索引延迟，自动保存使用 5 秒索引防抖；同一文件的重复任务必须继续合并。
- Agent 执行入口使用单一 `AgentRunRequest` 对象；外部工具事件必须先经 `agent/session.ts` 运行时解码，再写入聊天 store。
- Agent 开启流式输出时，执行层必须把当前模型响应的累计文本实时传给聊天 UI；同批次包含多个工具调用时，每个工具都必须分别发送带 `toolName` 的 `action` 与 `observation` 事件。

## Agent Router V2

- 每轮规则仅生成一次路由与分数。明确问答、明确工具意图、手动能力选择、既有 Agent 续接和纯选区翻译不等待语义模型；低分本身不触发兜底。
- 仅有类别竞争、隐含检索、缺失指代或隐含历史依赖证据时，允许一次有时限的语义分类。结构化结果允许 `no_tool`；模型只选已注册类别，候选直接进入资格校验，不重新进行规则评分或强制补调。
- 分类复用现有凭据绑定连接，可单独选择同连接下的模型；只发送受限长度的本轮问题、上下文存在性与类别/工具名元数据，不发送文档全文、历史全文、路径或配置。失败、无效输出、超时保留原规则结果；取消与迟到结果不得污染新请求。
- 工具选择不产生授权。暴露工具前与执行前均同步核验注册、启用/可用状态、桌面/数据库能力、Web 搜索开关、当前轮选区和可编辑目标；缺少可补充输入标为 `needs_input`，无权限或不可用标为 `blocked`。实际参数、文件路径与确认卡仍由既有工具及 Rust 边界独立校验。
- 明确记忆请求沿用规则检索；隐含需求可由同一次语义分类输出，`no_tool` 不排除独立记忆预检索。仍使用项目/全局作用域和 active 过滤；自动写入与候选确认遵守 `rag-memory.md`，工具分类本身不授予写入权限。
- 此分支基于不含 MCP 的稳定提交；经用户确认，本次只预留 `ExternalToolQualification/qualifyExternalTool` 元数据资格接口。不得把接口测试报告为真实 MCP Client/Server 集成通过；合并时必须接入实际连接/目录修订/本轮选择，并保留 main 的原生确认和串行执行边界，不能全量注入 Schema 或注册为内置工具。
- 阈值、预算与旧配置默认值集中在 `routerConfig.ts`。可选诊断仅在内存保留最近 200 次匿名耗时/原因/数量；误选与漏选需带标签的离线评测，不从模型置信度或是否执行工具推断准确率。

## 普通聊天核心检索

- Direct 可携带 `search_memory`、`search_knowledge` 两个精简 schema，由主模型按需选择；不额外分类或强制预检索。选区快速处理保持无工具。`routing.coreToolsEnabled` 缺省为 true，可在桌面设置关闭并恢复原 Direct 请求；关闭不禁用既有 Agent、记忆预检索或限定文件 RAG。
- 只执行一批、最多两个调用，再以无 tools 请求续答；不自动升级 Agent，不启用文本 JSON 调用兜底，不暴露写入、文件全文、联网或 MCP 工具。暴露前和执行前均复核资格、read effect 及 never confirmation；共享执行入口再次限制 Direct 只读白名单，沿用原参数、超时、取消和结果裁剪边界。
- Direct 捕获本轮工作区传给记忆工具，不建立全局 Agent scope。会话/工作区变化或取消后，不执行迟到调用、不注入迟到结果。查询参数不能自动授予敏感记忆读取权限。
- 同批默认 TopK 与显式等价参数共用 Promise；等价强记忆预检索复用已注入结果，空结果也复用。轻检索、分类限制、范围不同或细化 query 不冒充完整强检索。限定文件 RAG 不冒充全库查询；已注入知识片段仅在 chunk ID 和内容 hash 同时匹配时去重，保持原引用 ID。
- 原生 `assistant.tool_calls` / `tool.tool_call_id` 仅属于请求消息，不持久化为聊天角色；上下文溢出恢复必须保留当前轮调用及结果完整组，不重执行工具。
- 明确 tools 不支持错误且未输出任何内容时，最多无工具重试一次，并按当前 Provider 实例记住降级；其他请求错误不触发该降级。普通问答速度、真实模型误调用和原生兼容性必须实测，不以 mock 通过代替。

## 读取路由与完成校验

- “看看库里/库里面/库中……”或“库里有没有……”等范围＋查询动作组合识别为知识库读取，不把单字“库”、数据库或代码库自动当作知识库；无文件目标时不因“看看＋内容”推导出文件读取。弱词组合须来自至少两个不同能力，多个同能力弱词不独立触发 Agent。
- 具有 Agent 路由决策的非改写、非整篇文件总结、非选区快速处理或限定选区/章节读取任务，在原候选外补充资格允许的两个核心只读检索工具，并写回本轮路由候选，供执行和任务续接共同使用。复用 Direct 的启用、只读、无需确认和用户拒绝检索检查；不补充写入、文件全文、联网或 MCP 工具，不改变既有路径和作用域授权。
- 明确 required 的读取能力仅在成功工具结果（包括成功为空）或成功预检索后满足；失败或拒绝不算完成。语义分类的候选仍是建议，不因此强制检索。
- 缺少必需读取工具时直接说明缺失输入或不可用限制，不让无工具模型生成“准备检索”的承诺；模型未调用必需读取时最多自动补调一批，优先使用搜索而非库概览。补调后仍未满足则返回明确失败，不接受仅含行动说明的文本作为已完成回答；不通过匹配行动说明措辞来触发工具。
